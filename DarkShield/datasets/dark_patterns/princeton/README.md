## Files in This Directory

### 1. `dark-patterns.csv`
**Original reference CSV** containing all dark-pattern records from the Princeton crawl.

**Columns:**
- `Pattern String`: Human-readable description of the pattern
- `Comment`: Additional context or notes
- `Pattern Category`: High-level category (e.g., "Obstruction", "Nagging", etc.)
- `Pattern Type`: Specific pattern type within the category
- `Where in website?`: Location on the website (e.g., "Subscription cancellation")
- `Deceptive?`: Whether the pattern is deceptive (Yes/No)
- `Website Page`: URL or page identifier

**Source:** Downloaded from https://github.com/aruneshmathur/dark-patterns/blob/master/dark-patterns.csv

**Usage:** Reference dataset. Not parsed by the extension at runtime.

### 2. `dark-patterns.json`
**Lightweight JSON representation** derived from `dark-patterns.csv`.

Generated by `convert_csv_to_json.js` for efficient runtime access.

**Structure:**
```json
{
  "source": "Princeton Dark Patterns at Scale",
  "description": "Reference knowledge base derived from the Princeton dark-patterns dataset.",
  "records": [
    {
      "pattern_string": "...",
      "comment": "...",
      "pattern_category": "...",
      "pattern_type": "...",
      "where_in_website": "...",
      "deceptive": "...",
      "website_page": "..."
    }
  ]
}
```

**Notes:**
- All fields are normalized strings
- Missing values become empty strings
- Deceptive field is preserved as provided (Yes/No)
- Records maintain order from original CSV

### 3. `convert_csv_to_json.js`
**Node.js conversion utility** that transforms `dark-patterns.csv` → `dark-patterns.json`.

**Usage:**
```bash
node convert_csv_to_json.js
```

**What it does:**
1. Reads `dark-patterns.csv`
2. Parses CSV safely (handles quoted fields, embedded commas)
3. Extracts the 7 key columns
4. Normalizes missing/null values
5. Writes `dark-patterns.json`
6. Preserves original CSV unchanged
7. Reports conversion stats to console

**Error Handling:**
- Gracefully handles encoding issues
- Logs warnings for malformed rows
- Creates output even if some records fail

## How It's Used in the Extension

### Architecture

```
Browser Events
    ↓
analyzer.js (Behavior Detection)
    ↓
datasetMatcher.js (Reference Lookup)
    ↓
princetonPatterns.js (Runtime Knowledge Layer)
    ↓
dark-patterns.json (Reference Data)
```

### Process

1. **Analyzer** detects behavioral patterns from click events
   - Examples: excessive steps, repeated prompts, forced actions, etc.

2. **Matcher** looks up behavioral types in the reference taxonomy
   - Uses `princetonPatterns.js` as a lightweight knowledge layer
   - Maps internal behavior types to Princeton pattern categories
   - Returns relevant reference patterns with confidence scores

3. **Popup** displays results
   - Shows detected behaviors + reference patterns
   - Explains the connection to external literature
   - Does NOT claim the website is "proven" deceptive

### Key Points

- **Reference Only:** The matcher does NOT directly classify the live website based on Princeton data
- **Behavioral:** Detection is based on the user's interaction session, not on crawled website snapshots
- **Augmentation:** Reference patterns provide external validation context and taxonomy grounding
- **Transparency:** Users see both the detected behavior AND the reference source

---

## Important Distinctions

### What the Extension Does NOT Do

❌ Claim that Princeton contains the user's click-session data  
❌ Use Princeton to directly classify the current website as deceptive  
❌ Apply machine learning to match sessions to Princeton records  
❌ Treat Princeton as proof that a behavior is a dark pattern  

### What the Extension DOES Do

✓ Detect interaction friction from browser events  
✓ Match detected behaviors to similar pattern types in literature  
✓ Provide users with reference context from published research  
✓ Maintain transparency about the data sources and methods

## Data Quality Notes

- **Original Source:** 11,000+ websites crawled in 2019
- **Snapshot:** This is historical reference data, not a live service
- **Coverage:** Primarily e-commerce and subscription sites
- **Limitations:** 
  - Specific to 2019 web practices
  - May not reflect all current dark patterns
  - Geographically focused (primarily English-language sites)

## Conversion Details

### CSV → JSON Conversion

**Why JSON?**
- Faster parsing than CSV
- Cleaner integration with JavaScript
- Smaller file size when combined with extension bundle

**Why not inline in extension?**
- Large datasets stored separately to keep extension bundle small
- Optional loading (can gracefully degrade if unavailable)
- Easier to update reference data without extension redeployment

**Regeneration:**
To regenerate `dark-patterns.json` from `dark-patterns.csv`:
```bash
node convert_csv_to_json.js
```

## Testing

The extension test suite (`extension/analyzer/test.js`) includes test cases that verify:

1. Analyzer still works without reference data (graceful degradation)
2. Dataset matches are found for supported behavior types
3. Unsupported mappings return `NO_DIRECT_MAPPING`
4. Confidence scores reflect pattern strength, not ML probability
5. Output includes proper citations and "reference only" disclaimers

Run tests:
```bash
node extension/analyzer/test.js
```
